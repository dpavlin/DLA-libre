## 1. Bypassing the Wine GUI Blocker
Through active registry and file tracing (`WINEDEBUG=+reg,+file`), we identified the exact logic the Windows application uses to detect the DLA handheld compiler software:
1. It opens the registry key: `HKEY_LOCAL_MACHINE\SOFTWARE\3M\Library Systems\DLA`
2. It queries the string value: `Install` (e.g. `C:\Program Files\3M Library Systems\DLA`)
3. It opens the registry key: `HKEY_LOCAL_MACHINE\SOFTWARE\3M\Library Systems\Data Manager\3.00\BCValidation`
4. It reads the validation parameters: `MinLength`, `MaxLength`, `Digit Characters`, `Upper Case Characters`, `Lower Case Characters`, and `Other Characters`.
5. It searches the path resolved in (2) for handheld binaries: `DLA*.prc` and `FlashPro.prc`.

By writing the missing registry entries and copying the compiler files from the extraction archive to the root of `C:\Program Files\3M Library Systems\DLA\`, the GUI successfully initialized and completed the export sequence under Wine.

## 2. Key Format Insights
Detailed comparison of the PDB/PDX files produced by the two compilers revealed:
* **Record Size Differentiation:**
  * For datasets $\le 65,535$ records (e.g., Floor A), the barcode index (`.pdX`) uses **14-byte records** (10-byte barcode + 2-byte flags + 2-byte BE shelf order index).
  * For datasets $> 65,535$ records (e.g., Floor F), the barcode index (`.pdX`) uses **16-byte records** (10-byte barcode + 2-byte flags + 4-byte BE shelf order index).
* **Search Index Catalogs (`ndex/3F3F4431/` and `ndex/3F3F4432/`):**
  * Spacing is fixed at 1,024 records.
  * Title index entries are padded to **50 bytes**.
  * Callnumber index entries are padded to **38 bytes**.
* **PDB Data Record Padding:**
  * Title and Callnumber fields are formatted as `"title: <val>\x00"` and `"callnumber: <val>\x00"`, truncated case-insensitively to 40 characters in character space (not byte space), padded to **even size** individually, and concatenated.
